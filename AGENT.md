# mqtt-kafka-bridge guidance

Current scope includes message definitions, configuration, the generated MQTT-to-Kafka mapper and the user-authored telemetry processor whose QoS/topic wiring and correctness fixes were explicitly requested. Keep the existing bootstrap, standard Kafka infrastructure configuration and WebFlux/Actuator foundation. The user explicitly authorized completing MqttClientConfig: construct a disconnected HiveMQ MQTT 5 async client bean using bridge.mqtt.identifier, bridge.mqtt.host and bridge.mqtt.port. The user also authorized moving connectSubscriber into MqttClientConfig; keep it explicit, asynchronous and error-preserving. The telemetry processor injects its dependencies and must not initiate connection or subscription on startup. The user authorized fixing the existing subscription/forwarding code: use the configured Mqtt5Subscribe request, explicit subscribe() after connection, JSON byte serialization, deviceId keys, constructor-injected mapper/Kafka destination and asynchronous error logging. Do not add automatic startup, new routing, Cloud functions, retries, watering/device logic or additional processing without a later explicit request. HiveMQ MQTT Client replaces Paho; do not reintroduce Paho or its Spring Integration adapter. Preserve the MQTT 5 client selected in the user’s configuration class.

The intended bridge transports one complete MQTT observation into one complete raw Kafka record, keyed by deviceId. Separate downstream Device Processor and Telemetry Processor applications consume the raw topic using distinct groups. Keep envelope, battery/errors and sensor payload together in the message definitions. Soil is resolved downstream from sensorId. A device can report multiple sensors in different soils; never require soilId or assume one sensor/soil per device. No database, calibration, notifications, watering decisions or pump logic belongs here.

Exactly two authoritative OpenAPI documents under src/main/resources/openapi/ define MQTT input and Kafka raw output: mqtt-inbound.yml and kafka-raw-telemetry.yml. Shared payload/error schemas belong to inbound and are referenced by outbound. Preserve the supplied MQTT example and full outbound example. Generate message DTOs during Maven generate-sources and the explicitly authorized MapStruct mapper during compilation. The mapper converts one MqttTelemetryMessage to one complete KafkaRawTelemetry, preserving all fields, diagnostics and extensible sensor measurements. Keep strict source/target field checks and tests for different sensors. Generate no APIs/controllers or broker processing code. Never edit generated files under ignored target/.

Use Java 25 without preview, compatible stable Spring Boot, WebFlux/Reactor, Spring Kafka, Spring Cloud Stream/Function, HiveMQ MQTT Client, Maven Wrapper, JUnit Jupiter, Reactor Test and Testcontainers in one module. Lombok and SLF4J remain explicitly authorized, with Boot-managed versions and explicit Lombok annotation processing. No Spring MVC, Reactor Kafka, databases or Kubernetes. Pin unmanaged dependencies/plugins/images and verify compatibility using official documentation.

Follow TDD and KISS for meaningful changes: write/run a failing test, confirm its expected failure, then implement the smallest passing change. Report actual executions only. Avoid speculative layers or empty services. Use constructor injection and immutable typed properties. Update relevant tests/documentation. Preserve unrelated edits and the staged index.

Run ./mvnw test for Docker-independent fast tests. Run ./mvnw verify for the real Kafka connectivity test and HiveMQ/Mosquitto-to-Kafka integration test; Docker is required and must not silently skip. Use ./mvnw clean verify after deleting generated contracts/classes. Keep publishers, orchestration and bounded broker waits in tests. Await SUBACK before publishing, assert configured topic/QoS and key/payload, and disconnect test clients. Never claim connectivity from unit tests alone.

Keep standard Kafka settings under spring.kafka.* and MQTT/topic settings under bridge.*. Do not restore obsolete Cloud function definitions or bindings; function autodetection stays disabled while the existing Stream dependency remains installed. The explicit processor publishes through KafkaTemplate. Keep only settings consumed by the current code; unused MQTT credentials/timeouts and production Kafka consumer/listener settings were removed. Test consumer configuration stays isolated. MqttClientConfig creates a validated Mqtt5Subscribe bean from bridge.mqtt.telemetry-topic and numeric bridge.mqtt.qos (0, 1, 2 only). The processor receives its Kafka destination from bridge.topics.telemetry. No startup broker connections or automatic topic provisioning. Only health/info are exposed by default. Keep test config isolated from developer settings.

Keep WebFlux reactive. Future integrations must avoid .block(), .join(), Thread.sleep() and blocking broker operations in production event paths; cleanup must be bounded, asynchronous adaptation lazy and error-preserving. Do not claim end-to-end backpressure or exactly-once delivery from configuration declarations.

Secrets stay outside Git and logs. .env.example contains placeholders only; the JVM does not automatically load .env. Use environment overrides, standard Kafka security properties and optional MQTT credentials with redacted configuration. Anonymous MQTT/plaintext Kafka are local/test only. AGENTS.md points here as the single authoritative instruction source.

GitHub Actions CI and release workflows live under .github/workflows. Preserve the selected self-hosted build/publication runners (Linux with Bash; publication also needs gh) and require Docker; never silently skip broker tests. CI uses Java 25 and Maven Wrapper clean verify, uploads reports and the verified JAR. Version tags reuse CI before publishing that same artifact to GitHub Releases; publishing is confined to a separate job with contents:write. Pin actions by immutable SHA and keep checkout credentials unpersisted. Validate workflow changes with actionlint and update README runner/release instructions. Do not trigger releases, push tags or deploy merely to test workflow files.

Keep root compose.yml limited to the mqtt-kafka-bridge service. Kafka/Mosquitto belong only to infra/compose.yml; neither stack owns the other's lifecycle. Both join an explicitly created external gladys network (GLADYS_NETWORK override). Preserve host/internal Kafka advertised listeners and use kafka:29092 / mosquitto:1883 for container clients. Root Compose explicitly loads BRIDGE_ENV_FILE (default .env); server env files belong outside Git, e.g. /etc/gladys/mqtt-kafka-bridge.env with mode 600. Explain Compose interpolation vs container env_file loading. The Dockerfile packages a verified prebuilt JAR on a digest-pinned Java 25 JRE and runs unprivileged; .dockerignore must exclude env files/source/Git data. CI validates both stacks and builds the image. Check independent lifecycle, environment loading and health with isolated Compose project/network names; clean up only owned test resources. Do not add automatic MQTT startup while changing deployment configuration.
